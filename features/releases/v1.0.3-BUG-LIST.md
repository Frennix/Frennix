## How to add an issue

1. Assign the next ID: `BUG-003`, `BUG-004`, … (or `ENH-001` for enhancements).
2. **Classify severity first** — P0–P3 per [`BUG-SEVERITY.md`](./BUG-SEVERITY.md). Fill priority, version found, version fixed (`—` until shipped), status, and assigned milestone.
3. Add a row to **Open issues** above (or copy [`templates/BUG-REPORT-TEMPLATE.md`](./templates/BUG-REPORT-TEMPLATE.md)).
4. Mirror the row in [`RELEASE.md`](./RELEASE.md) → v1.0.3 → Bug fixes (and Known Issues if user-facing).
5. Fix only after classification and logging are complete.

**Critical User Flows failure:** Any ❌ during [`CRITICAL-USER-FLOWS.md`](./checklists/CRITICAL-USER-FLOWS.md) verification → create bug here **immediately** (include flow ID, e.g. `INT-05`, plus Device and Browser) before fixing.

**Postmortem required:** Production bugs discovered by users cannot be **Closed** until [`POSTMORTEM-PROCESS.md`](./POSTMORTEM-PROCESS.md) is complete — create `postmortems/BUG-XXX-POSTMORTEM.md` when the bug is logged.

### Severity guide (P0–P3)

Full definitions: [`BUG-SEVERITY.md`](./BUG-SEVERITY.md)

| Severity | Priority | When to use |
|----------|----------|-------------|
| **P0** | Fix immediately | Crash, login failure, data loss, security, production outage |
| **P1** | Next patch release | Core feature broken; significant user impact |
| **P2** | Next planned release | Feature works but buggy, UI issues, degraded performance |
| **P3** | Backlog | Cosmetic, minor UX, nice-to-have |
